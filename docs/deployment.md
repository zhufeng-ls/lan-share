# 部署与维护

## 固定入口与 Nginx

可以将自有子域名解析到服务器内网 IP，或使用内网 DNS。域名本身不提供公网转发，访问设备仍需能够连接该内网；服务器 IP 变化后也要同步更新解析。

如需使用 `http://share.example.com` 而不显示端口：

1. 应用保持 `BIND_IP=127.0.0.1`、`PORT=8787`。
2. 按 [Nginx 示例](../deploy/nginx.example.conf) 将域名改为自己的域名，加入主机现有 Nginx 站点配置。
3. 在 `.env` 设置 `PUBLIC_URL=http://自己的域名`，重新创建应用容器。
4. 执行 `sudo nginx -t`，通过后再执行 `sudo systemctl reload nginx`。
5. 从另一台局域网设备验证域名访问、身份记忆、上传和下载。

示例只添加一个命名虚拟主机，不替换已有站点或设置默认站点。80 端口若已被其他服务占用，应先核对现有用途。使用代理软件的客户端可能需要将该内网域名设为直连。

本示例仅覆盖 HTTP。应用会校验请求 Origin 与自身看到的协议、Host 是否一致；不能仅添加 TLS 终止就认为 HTTPS 配置完成。HTTPS 需要同时处理受信代理和来源校验，再启用 `COOKIE_SECURE`。

## 服务管理

所有命令在项目根目录运行：

```sh
./manage.sh ps
./manage.sh logs --tail=100
./manage.sh restart
./manage.sh stop
./manage.sh start
```

更新源码后的重建方式兼容旧版 Compose：

```sh
./manage.sh build
./manage.sh stop
./manage.sh rm -f
./manage.sh up -d
```

`.env` 改动也需要重新创建容器，普通 `restart` 不会重新加载 Compose 配置。应用项目名固定为 `lan-share`，数据卷固定为 `lan-share_lan-share-data`。不要执行 `down -v`，该命令会删除数据卷。

## 备份与恢复

回收站位于同一块磁盘，不能代替独立备份。运行：

```sh
./backup.sh /绝对路径/lan-share-backup.tar.gz
```

目标父目录必须存在，脚本拒绝覆盖已有文件。它短暂停止服务，以一致状态备份整个数据卷，然后恢复原本运行中的服务。备份包含身份凭证数据库、管理员密码哈希、文件和历史，应妥善保存。

向一套空部署恢复时，先构建镜像与创建容器、卷，再导入：

```sh
./manage.sh build
./manage.sh create
docker run --rm --user 0:0 \
  -v lan-share_lan-share-data:/data \
  -v /备份所在目录:/backup:ro \
  lan-share:1.0.0 sh -c \
  'test ! -e /data/index.sqlite3 && tar -xzf /backup/lan-share-backup.tar.gz -C /data && chown -R 10001:10001 /data'
./manage.sh up -d
```

示例拒绝覆盖已有数据库。现有实例需要先另行备份并停止服务，再安排恢复；不要在运行期间手工修改数据库或文件。

## 管理员整理规则

- 停用用户：撤销所有普通会话，保留文件和目录；恢复后需要重新进入。
- 回收目录：列表和旧链接都不可访问，相关默认目录改为公共目录。
- 恢复目录：恢复原文件，不自动恢复之前的收藏和默认入口。
- 恢复用户：若已有启用中的同名用户，操作会被拒绝。
- 公共目录不能回收；当前没有永久清空管理回收站的按钮。

对于旧版本遗留的多个启用中同名身份，升级唯一名字约束前，应先通过旧版管理界面辨认目录和文件，停用重复身份。不要直接合并目录或按名字删除资料。

## 容量管理

每位用户所有目录合计 20 GiB，公共目录另设 20 GiB 共享池。当前文件、覆盖历史、回收内容及已归档目录一并计费。按目录所有者计算，与操作人无关；停用用户或新建目录不会重置容量。

上传和快速拷贝预留容量，成功提交后将预留转为实际用量；失败或取消会释放临时占用。空间不足会拒绝新增写入，不删除已有文件；恢复与移动文件不重复计费。页面显示用量，管理员也可以查看每个用户的用量。

容量统计基于存储中的实际文件大小，服务重启后仍然有效。管理员回收不能释放额度，当前没有永久清理界面；不要把“移入回收站”当成腾出空间。服务器整体磁盘不足时也可能拒绝写入，即使某位用户尚未达到额度。

## 存储布局

Docker 卷挂载在容器 `/data`；本地开发可用 `DATA_DIR` 指定其他目录。

```text
/data/
  index.sqlite3       # 用户、会话、目录、收藏、历史索引及管理记录
  files/<目录 ID>/    # 当前共享文件
  trash/              # 删除内容与覆盖前版本
  temporary/          # 上传、复制过程中的临时文件
```

容器以非 root 用户运行，根文件系统只读，仅数据卷和临时区可写。应用拒绝路径穿越和符号链接，下载以附件提供；上传文件不会作为本站 HTML 页面执行。部署只启动一个写入进程，不要让多个容器共同写同一个卷。
